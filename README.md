# dom-resident

Адаптивный веб-интерфейс личного кабинета собственника для управляющих компаний и ТСЖ. Работает с общим REST API проекта `dom-backend`.

## Возможности

- Регистрация по подтверждённой электронной почте, вход и восстановление пароля.
- Просмотр профиля и объектов недвижимости с характеристиками и долями собственности.
- Просмотр индивидуальных счётчиков, показаний и расхода.
- Передача накопительных показаний с комментариями.
- Исправление собственных показаний в открытый период и просмотр истории изменений.
- Установка на главный экран iPhone и Android с логотипом ТСН и названием «ТСН МР17дом1».

Доступ к объектам и допустимость изменений проверяет бэкенд. Для работы требуется совместимая версия API кабинета; этот репозиторий содержит клиентское приложение.

## Технологии

Vanilla JavaScript (ES modules), HTML и CSS. Сборка приложения и установка npm-зависимостей не нужны. Для тестов используется встроенный Node.js test runner, для обслуживания приложения — Caddy.

## Локальный запуск

Требуются Node.js 22+ и Caddy 2. Запустите совместимый бэкенд на `127.0.0.1:8080`, затем выполните:

```bash
npm test
caddy run --config dev/Caddyfile
```

Приложение доступно по адресу `http://localhost:3001`. Запросы `/api/v1/resident/*` направляются на локальный API. Учётные записи, подтверждение почты и отправка писем настраиваются на стороне бэкенда.

## Docker

```bash
docker build -t dom-resident:local .
```

Пример параметров Compose находится в `.env.example`. `RESIDENT_HOST` задаёт домен приложения, `API_UPSTREAM` — адрес API внутри контейнерной сети. Приложение использует API на том же origin; конфигурация Caddy проксирует запросы кабинета и закрывает административные маршруты.

## GitHub Actions

Push в `master` и pull request запускают тесты. Публикация образа и SSH-деплой включаются переменной репозитория `DEPLOY_ENABLED=true` после настройки собственного окружения.

Workflow использует secrets `DOCKER_USERNAME`, `DOCKER_TOKEN`, `DEPLOY_HOST_IP`, `DEPLOY_HOST_USERNAME`, `DEPLOY_HOST_PORT`, `DEPLOY_HOST_KEY`, `DEPLOY_HOST_PROJECT_PATH` и variables `RESIDENT_HOST`, `APP_NETWORK`, `PROXY_NETWORK`, `API_UPSTREAM`. Внешние сети и обратный прокси должны быть настроены заранее. Проверка после запуска подтверждает доступность HTML и API кабинета (`/api/v1/resident/healthz`) через прокси. При неудачной проверке workflow восстанавливает предыдущую конфигурацию.

Реальные параметры окружения, ключи и внутренняя документация хранятся вне Git. `.env` и каталог `private/` исключены из репозитория и Docker-контекста.

## Установка на телефон

Откройте кабинет по HTTPS. На iPhone в Safari выберите «Поделиться → На экран Домой»; на Android в Chrome — «Добавить на главный экран» или «Установить приложение». Название ярлыка — **ТСН МР17дом1**, иконка — предоставленный логотип ТСН. После установки кабинет открывается отдельным окном.

Для iPhone подготовлена непрозрачная PNG-иконка 180×180, для Android — 192×192 и 512×512. Логотип сохранён с отступами для круглых и скруглённых иконок. Если старый ярлык уже добавлен с другим названием или картинкой, удалите его и добавьте заново.

Для работы с профилем и показаниями нужен интернет. Service worker сохраняет только публичную страницу отсутствия сети и иконки; API, персональные данные и отправки показаний не кэшируются и не ставятся в офлайн-очередь. При изменении иконок или `offline.html` увеличивайте версию `CACHE_NAME` в `sw.js`. Манифест, service worker и иконки включены в Docker-образ.

## Интерфейс и передача показаний

Боковое меню содержит «Показания», «Недвижимость», «Двор и паркинг» и «Профиль»; на телефоне оно открывается по кнопке меню. После входа открывается передача показаний, а при отсутствии действующих счётчиков — недвижимость. Объекты без счётчиков не содержат перехода к показаниям. Дополнительные характеристики, комментарии, история и архивные приборы свёрнуты.

Даты приёма определяются сервером по московскому времени: ежемесячное расписание и исключения для конкретного месяца задаются администратором. До открытия и после закрытия доступен просмотр; месяц и срок указаны явно. Одна кнопка на помещение передаёт все заполненные приборы в одной транзакции. Пустое поле не означает ноль. Кнопка «Без изменений» повторяет предыдущее значение. При ошибке значения и комментарии сохраняются в форме.

Требуется бэкенд с миграцией `0042` и методом `POST /api/v1/resident/properties/{id}/readings`. Совместимый API возвращает эффективный период, московскую дату сервера и дату следующего открытия.

## Ручное обновление приложения

Кнопка «↻ Обновить» справа сверху доступна на экране входа и внутри кабинета, включая установленное PWA. Она проверяет связь с сервером, обновляет service worker при наличии новой версии и перезагружает текущий раздел, сохраняя авторизацию. JS и CSS проверяются на актуальность сервером при повторной загрузке.

При неотправленных изменениях показаний, комментариев или других форм появляется подтверждение. Автоматически заполненные поля предупреждение не вызывают. Во время сохранения обновление недоступно. При отсутствии сети или ошибке обновления страница и введённые значения сохраняются; ожидание ограничено десятью секундами. Cookie авторизации и регистрация PWA не удаляются.

## Двор и паркинг

Заявки по умолчанию показывают ожидающие и действующие доступы. Чекбокс «Показать отклонённые» добавляет к списку отклонённые, отменённые и утратившие силу заявки.

Раздел `#access` позволяет собственнику подать заявку на доступ, увидеть решение и историю, отменить ожидающую заявку и отозвать ранее одобренный доступ. Для новой заявки на основе отклонённой/истёкшей сохраняются выбранные объекты, контакт и автомобиль. Данные после отправки не редактируются: отмените/отзовите прежнюю заявку и отправьте новую.

Объекты выбираются чекбоксами: например, «Квартира 16» и «Машиноместо 178», без адреса. Хотя бы один объект обязателен; единственный выбирается автоматически. Квартира или коммерческое помещение даёт доступ во двор, машиноместо — в паркинг, поэтому отдельного выбора зоны нет. На несколько объектов отправляется одна заявка, а охрана принимает одно решение. Отправка атомарна: при ошибке любого объекта не сохраняется ни одна часть.

Телефон вводится с маской `+7 926 793 63 63` (поддерживаются вставка и исправление цифр). Получатель выбирается радиокнопками: собственник, арендатор, родственник, гость. Поля номера и марки автомобиля открыты сразу; галочка «Нет личного автомобиля» отключает их и отправляет заявку без данных авто. Комментарий доступен сразу. Срок действия в новой форме не задаётся; ранее сохранённые ограничения продолжают учитываться.

Список показывает одну карточку для всех объектов заявки. Отмена, отзыв и история относятся ко всей заявке. При утрате собственности на часть объектов их индивидуальные статусы видны в карточке; оставшиеся действующие основания сохраняются. Каждый совладелец видит только свои заявки. Требуется backend с миграцией `0049`.

Первый этап фиксирует заявки и решения в сервисе. Открытие ворот и шлагбаумов через оборудование ещё не подключено. Требуется backend с миграцией `0049`.

### Этапы и текущее состояние

- [x] Заявки жителя: объект/зона по собственности, телефон и получатель, телефон с маской, необязательное авто и комментарий.
- [x] Проверка охраной/администратором в существующей админке; отдельная роль охранника без доступа к другим разделам.
- [x] Отмена, отзыв, история решений, блокировка повторов, учёт срока и действующего владения.
- [ ] Интеграция с микросервисом ELDES: доставка изменений, подтверждение устройства, повторы и сверка, вход/выход по каждой зоне.
- [ ] При интеграции объединять действующие основания одного телефона и автоматически учитывать продажу/истечение срока.
- [ ] При необходимости отдельное приложение охраны на том же API и уведомления о решениях.

Не создавайте учётные записи охраны с общим административным доступом. Учётная запись роли «Охрана» создаётся администратором в разделе пользователей; реальные пароли и инфраструктурные настройки в публичной документации не хранятся.

В списке и фильтре заявок используются только «На проверке», «Одобрено», «Отклонено» (жёлтый, зелёный и красный). Отменённые/отозванные заявки, истёкший срок или утрата права у ранее одобренных заявок отображаются в категории «Отклонено» с пояснением. Если действует хотя бы одно основание, общая заявка остаётся «Одобрено», а ограничение другого объекта поясняется рядом с ним. История действий и проверки прав сохраняются.

Ожидающая решения заявка остаётся «На проверке», даже если право на объект прекратилось; одобрить её нельзя, охрана может отклонить с причиной.

### Автомобили и коммерческие помещения

Собственники коммерческих помещений могут подавать заявки во двор наравне с собственниками квартир. В одной заявке можно указать до 10 автомобилей кнопкой «Добавить автомобиль», удалить лишние строки или выбрать «Нет личного автомобиля». Список и карточка показывают все действующие машины; снятые с использования сохранены в раскрывающемся архиве. При создании новой заявки на основе прежней архивные машины не добавляются. Требуется backend с миграцией `0050`.
